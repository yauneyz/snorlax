We want to build a second Android app (besides talysman-insights) that is actually a distraction blocker. So we have Talysman for Android now (which is a port of our desktop app) and the insights app (which is for internal use only)

This app is basically a desktop port of our existing app, but instead of a usb key we use an nfc tag or qr code scan.

It will have an on/off mechanism like the foqos/Brick app - you can pair an nfc tag or qr code scan with the app, then that is what is required to turn off focus.

5 emergency unlocks ever, just like Brick. (for now)

We operate with either a blacklist or whitelist of apps on the phone.

But we also incorporate softblocks. So like the BlockScroll app for Android, we give the ability to block short form content like YouTube shorts, Instagram Reels, etc.

We also implement our browser-level soft blocker filtering, to filter out feeds/etc.

We *also* implement what ScreenZen has where we allow the user to set a # of times they are allowed to disable the blocker per day, plus how long each override lasts.

Also, we track the # of days the user goes without disabling their blocker or their relaxing it. Tightening it is allowed. This is a visible streak that is shown any time they try to override the blocker. Also when they try to override we have a nice UI showing how many unlocks they have left. Just look at the screenzen UI in inspiration_screenshots. That is the popup that shows when someone tries to get into an app that is in their hard block list.

So the way our block works:
- there are hard blocks of entire apps. Either because of blacklist or whitelist
- there is also the option to add a soft block. We only offer soft blocks for certain sites (the list will continue to grow). A soft block comes with browser-level manipulation to remove feeds as well as using accessibility to neuter the app itself as best as possible while leaving library/messaging functions intact.
- Hard block + soft block = hard block. Whitelist uninclude + soft block = soft block
- you also have the option to set up groups of apps that are "overrideable" - the override gets rid of all blocks on the app, hard or soft.
- For overrides, you can create different groups of apps that share a pool of unlocks, each pool having its own #/duration.

When a person wants to override, there are a couple ways to do it.
1) Turn off the blocker completely, stays off until re-enabled (like Brick)
2) Turn off just a subset of blocks until re-enabled (we have a re-enable all button)
3) Temporarily turn all blocks temporarily, for like 10 min, an hour, etc. This way when you are done doing whatever you are doing you can automatically be protected again

We also allow scheduling - like block is automatically turned on/off at certain times. (a schedule can also be just "on at x time" and "off at x time")

You can also pre-schedule a one-time on/off command to be executed at some future date/time

The override and scheduling/etc and the screenzen-style pooling should all also be included in the desktop app

Multiple blocking profiles allowed. All the config I just mentioned belongs to a single profile. And for ease of setup, we should allow the user to duplicate a profile.

Given that the android app and the desktop app have so much in common, we should really work to make sure that we factor as much functionality as possible into a shared space. We want to really not duplicate functionality.

No AI mode on the app yet.
